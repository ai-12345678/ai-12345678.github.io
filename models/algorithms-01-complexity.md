## 要解决的问题

音频处理中经常需要计算一段窗口内的能量。相同的结果，可以用不同的计算量得到。算法分析帮助判断处理长录音时的时间与内存成本。

先修知识：数组、循环与求和。

## 时间复杂度和空间复杂度

大 O 描述输入规模增长时的渐近上界，不能直接换算为运行秒数。需要说明分析的输入规模、最坏或平均情况，以及空间统计口径。

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 已知索引访问数组 | O(1) | 常见随机访问模型 |
| 扫描 N 个点 | O(N) | 每点常数次操作 |
| 通用比较排序 | O(N log N) | 存在达到此上界的算法 |
| 每个位置重算 W 点窗口 | O((N-W+1)W) | 1 ≤ W ≤ N |
| 滑动更新所有窗口 | O(N) | 初始求和后每次移入、移出 |

当 W 是固定常数时，重算方案也可以写成 O(N)；把 W 单独列出来更能解释不同窗口长度的成本。

## 案例：滑动平均能量

长度 W 的窗口能量定义为：

`E[k] = (x[k]^2 + ... + x[k+W-1]^2) / W`

相邻窗口大部分内容相同，因此只需移出旧采样、移入新采样：

`S[k+1] = S[k] - x[k]^2 + x[k+W]^2`

下面两种实现返回同样数量的有效窗口，不进行边缘补零：

```python
def energy_naive(x, w):
    if not 1 <= w <= len(x):
        raise ValueError("窗口必须介于 1 和输入长度之间")
    return [
        sum(x[j] ** 2 for j in range(i, i + w)) / w
        for i in range(len(x) - w + 1)
    ]

def energy_sliding(x, w):
    if not 1 <= w <= len(x):
        raise ValueError("窗口必须介于 1 和输入长度之间")
    total = sum(v * v for v in x[:w])
    out = [total / w]
    for i in range(w, len(x)):
        total += x[i] ** 2 - x[i - w] ** 2
        out.append(total / w)
    return out

x = [1.0, -2.0, 3.0, -4.0]
expected = [2.5, 6.5, 12.5]
assert energy_naive(x, 2) == expected
assert energy_sliding(x, 2) == expected
print(expected)
```

滑动方案除输出外占用 O(W) 额外空间，因为 Python 的 x[:w] 会复制切片；可用索引生成器求和消除该临时切片。返回的输出列表占 O(N-W+1) 空间。真正的流式输入通常还需要 O(W) 环形缓冲区保存移出值。

## 工程取舍

- 平均平方能量与 RMS 不同：RMS = sqrt(E)。能量阈值可用于简单活动检测，但背景噪声会误触发，不能等同于完整 VAD。
- 长期浮点滚动求和可能积累误差；可定期重算窗口和，并用容差比较参考实现。
- 大 O 不反映 Python 与向量化库的常数差异。实测速度要记录输入长度、窗口大小、硬件及实现版本。

## 自测

1. N=16000，W=320，有效窗口数是多少？答：15681。
2. 为什么滑动算法不用重新加 320 个值？答：相邻窗口只变了两个采样点。
3. 输出改成生成器一定只需要 O(1) 内存吗？答：不一定；流式窗口仍需存储将被移出的数据。
